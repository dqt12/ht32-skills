## 1. 时钟配置顺序（顺序错了就是随机故障）

1. **选源**：内部 RC（快、精度低）还是外部晶振（精度高）；需要更高主频再决定是否开 PLL
2. **确认上限**：目标频率必须在芯片规格内（查 wiki 芯片页的 max clock），再算总线分频
3. **先门控后配置**：先开外设时钟，再写外设寄存器；关外设前先停传输 / 关中断
4. **按实际总线时钟算参数**：串口波特率、定时器周期、SPI 速率都依赖真实总线频率，
   不按"标称值"算；改了时钟就必须重算所有时序参数
5. **改时钟的最小影响面**：先确认哪些外设依赖它，改完逐个复测

### 启动时钟取证

- 找出启动文件、`SystemInit`、系统时钟更新函数与应用二次改时钟的位置；以 code MCP 核实实际工程所用文件、调用顺序和库 API，不按文件名或芯片系列推断。
- 分别记录复位默认时钟、启动阶段最终选择的源/PLL/分频，以及后续运行期可能改写时钟的代码。每一项标注代码位置与 MCP 依据；找不到证据就标未知。
- 软件变量（如 `SystemCoreClock`）是软件对主频的记录，不是物理测量。核对其更新函数是否在最终时钟切换后调用、实现和分频定义是否与寄存器配置一致；不能据此单独宣称实测主频。
- 把「配置推导的主频」「软件记录的主频」和「板级测得的主频」分开报告。测量方法和结果按下方板级实测清单记录。

## 2. 低功耗模式怎么选

| 概念类别（不保证该型号存在） | 设计时核对的问题 |
|---|---|
| Sleep / 浅睡眠 | 哪些时钟和外设继续运行？哪些中断可唤醒？ |
| DeepSleep / 深睡眠 | SRAM / 寄存器哪些保留？唤醒后时钟源与分频是什么？ |
| 更深层待机模式 | 哪些唤醒源仍供电？是否需要重新初始化外设？ |

这些是**问题分类，不是模式对照表**。具体模式名、寄存器位、可用唤醒源、保留域与唤醒后时钟，
逐型号以数据手册 / wiki MCP 为准；不得把一颗芯片的结论套到同系列其他型号。

## 3. 进低功耗前检查清单

- 未用外设的时钟全部关闭（漏一个就可能高一个数量级）
- 未用 GPIO 设为确定电平，浮空脚会漏电
- 唤醒源已使能，且其中断优先级 / 屏蔽状态正确
- 调试器连接会影响低功耗行为——用调试器测得的电流不作数
- 串口最后一帧发送完成再进（否则丢帧）
- 进入前把关键状态存进 `xxx_t`，醒来据此恢复

## 4. 唤醒后要恢复什么

先从目标型号资料确认唤醒后的时钟和保留域，再决定恢复内容；下面是检查项，不代表所有模式都需要重配：

- **时钟**：确认时钟源、PLL、分频器是否保留或回到复位值，再决定是否重新配置
- **外设**：逐项检查串口、DMA、定时器的寄存器与使能状态，不能默认仍在工作
- **状态**：逐项确认 `xxx_t` 与 SRAM 是否保留；若未定义或无证据，按状态丢失处理

## 5. 怎么验证（没有测量就不算完成）

### 板级实测记录

每次核验记录目标型号/封装、板卡版本、供电条件、探测点与仪器、固件版本/构建配置、测试步骤、原始读数和日期。至少逐项核对：

- 时钟：启动源与 PLL/分频的代码证据、软件主频变量及更新时机、GPIO/MCO 等可观测输出的测量频率；条件不允许测量时明确写「未实测」。
- UART：板级实际连接的调试 UART 实例、TX/RX 引脚与跳线/USB-UART 通道；记录固件配置值、串口工具设置、是否收到字节及原始日志。不要仅凭配置宏或默认值认定接线正确。
- 调试器：实际探针型号、Keil 工程所选驱动、目标板供电与连接方式、连接/下载结果。J-Link 型号/固件与 Keil 驱动配置分别记录；兼容性不能只凭出现 J-Link 选项推断，须以当前安装版本、工程配置和板级连接实测确认。
- 结果：区分规格上限、代码配置值、软件报告值与仪器测量值；注明未覆盖项目、误差/限制与证据来源，不把单块板的结果外推到其他型号或板卡。

| 目标 | 方法 |
|---|---|
| 功耗 | 万用表串在供电回路测平均电流，与手册典型值对比；差一个数量级 = 有外设没关 |
| 唤醒 | 每次唤醒翻转一个 GPIO 或累加计数，串口打出来 |
| 实际主频 | 配一个 GPIO 翻转（或 MCO），用示波器 / 逻辑分析仪测频率反推总线时钟 |
| 唤醒延迟 | 进之前翻转 GPIO 一次、醒来再翻转一次，测两次边沿间隔 |
