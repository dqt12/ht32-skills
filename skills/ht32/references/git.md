# Git 版本控制集成（共享口径）

> 本文件是 `ht32` 主 Skill 的内部参考，不是独立工作流。工程无仓库时的询问、初始化，
> 以及后续功能提交的规则只在这里定义；`project-create` / `dev-assist` 只引用，不重复。

## 1. 检测工程根状态

在工程根执行一次，按 `--show-toplevel` 输出分三种状态：

```powershell
git -C "<project-root>" rev-parse --show-toplevel
```

| 结果 | 状态 | 处理 |
|---|---|---|
| 命令失败（不是仓库） | 无仓库 | 走第 2 节：**先询问用户**是否启用 Git |
| 输出 == 工程根（路径归一化后比较） | 工程自身仓库 | 建工程交付按第 3 节**先确认再提交**；dev-assist 按第 4 节自动提交；第 8 节无记录时先问一次是否自动提交 |
| 输出 == 上层目录 | 位于父仓库内 | **不初始化、不自动提交**（避免把工程外文件带进提交）；告知用户实际仓库根，提交由用户决定 |

- `git` 不可用 → 记 warning 并跳过，不阻断工程交付
- 不要用目录名、`.git` 是否存在等猜测代替上面的实测

## 2. 无仓库：询问与初始提交

**必须先问用户**，不静默初始化：

> 当前工程还没有 Git 版本控制。要我为本工程初始化 Git 仓库吗？初始化后会做一次初始提交，
> 后续每个功能完成自动提交（只提交到本地，不推送）。

- **用户拒绝** → 在工程 `HT32_PROJECT.md` 第 8 节「项目追加约定」记
  `Git：未启用（用户拒绝 YYYY-MM-DD）`；本工程后续会话不再询问，用户改主意时按本节重新启用
- **用户同意** → 依次执行：
  1. 在工程根 `git init`
  2. 工程根没有 `.gitignore` 时写入下面的模板；已存在且内容不同 → 询问用户，**不覆盖**
  3. `git add -A`：按目录结构整体纳入，受 `.gitignore` 约束
  4. `git commit -m "chore: 初始化 <工程名> 工程"` —— **初始工程只做这一次提交**
  5. 在 HT32_PROJECT.md 第 8 节记 `Git：已启用（初始提交 <短 sha>；后续功能自动提交）`
- 提交前检查 `git config user.name` 与 `git config user.email`：为空时不代设任何配置，
  提示用户自行配置后重试；不阻断工程交付
- 初始提交失败（钩子 / 权限 / 身份）→ warning + 原始报错，交付继续，**不反复重试**

`.gitignore` 模板（Keil 工程 + skill 本机配置；按工程实际输出目录调整）：

```gitignore
# Keil 构建产物
**/Objects/
**/Listings/
**/*.uvguix.*
*.dep
*.bak-*
# 打包 / 传输产物
*.zip
# skill 本机配置
.ht32-skills/
```

## 3. 工程已是自身仓库：创建前预检与交付提交（project-create）

### 3.1 创建前预检（写任何文件之前）

- **前提**：第 1 节状态为「工程自身仓库」。在导出 / 落盘 / 写任何文件之前执行 `git status -s`
- **无输出** → 继续创建
- **有未提交改动** → 展示 `git status -s` 摘要，**先询问**：
  > 目标工程目录已有未提交改动。要先把这些改动提交一次，再开始创建吗？
- **用户同意** → `git add -A` + `git commit -m "chore: 创建 <工程名> 前提交现有改动"`，
  成功后继续创建；提交前检查身份（同第 2 节）
- **用户拒绝** → **停止创建**，请用户先自行 commit / stash / 清理后再开始；
  不把新工程与旧改动混在一起
- 提交失败 → 停止创建并给出原始报错，不继续落盘

### 3.2 交付提交（创建完成、交付收尾之后）

- 交付收尾后先执行 `git status -s`
- **无输出** → 跳过，并在第 8 节记 `Git：已启用（已有仓库）`
- **有改动** → 把 `git status -s` 摘要展示给用户，**先询问**：
  > 工程已在 Git 仓库中。本次交付产生了以下未提交改动，要提交一次作为交付基线吗？
- **用户同意** → `git add -A` + `git commit -m "chore: 交付 <工程名> 初始工程"`；
  一次交付只提交一次；提交前检查身份（同第 2 节）；不改分支、不改配置、不 push；
  第 8 节记 `Git：已启用（已有仓库；交付提交 <短 sha>）`
- **用户拒绝** → 不提交，汇报里说明「改动保留在工作区，未提交」；
  第 8 节记 `Git：已启用（已有仓库；交付改动未提交）`
- 3.1 已提交过现有改动时，这里的 `git status -s` 只会包含本次新建/修改的文件
- 已有历史、分支、tag 一律不动；父仓库状态不走本节（见第 1 节）

## 4. 后续功能提交（dev-assist）

- **前提**：工程根就是仓库根，且 HT32_PROJECT.md 第 8 节为 `Git：已启用`
  - 已有仓库但第 8 节无记录 → 先问一次「后续功能完成后要自动提交吗？」再记入第 8 节
  - 状态为父仓库 / `Git：未启用` → **不提交**
- **时机**：编译通过、HT32_PROJECT.md 更新完成之后，**一次任务一次提交**
- **范围**：只 `git add` 本轮改动的文件与 `HT32_PROJECT.md`；**不用 `git add -A`**，
  不把会话开始前就存在的未提交改动带进本次提交
- **消息**：conventional commits，按本轮性质写
  `feat(<模块或工程名>): <一句话功能>` / `fix(<模块>): <一句话修复>`；
  正文可列关键文件与 HT32_PROJECT.md 依据；不使用跳过钩子的参数
- **不提交**：编译未通过 / 本轮无文件变化 / 用户明确要求不提交
- 提交失败 → warning + 原始报错，交付继续；不重试、不改 Git 配置
- 交付汇报附本次 commit 短 sha；用户要求查看时用 `git show <短 sha>`

## 5. 安全边界（不可越界）

- 只做本地 `init` / `add` / `commit`；**不 push、不 fetch、不 pull、不改 remote、不建 tag 或 release**
- **不** rebase / reset / amend / 强推 / 重写历史
- **不**修改任何 Git 配置（含全局配置）；缺身份让用户自己配
- 不提交构建产物、固件归档、`.ht32-skills/`、运行日志；这些应在 `.gitignore` 内
- 用户明确说「不要自动提交」→ 以用户为准，改记第 8 节；初始化的那一次提交仍须用户同意
